# Kaltura Product Design Working Rules

Always think critically.
Prefer user outcomes over features.
Use JTBD before proposing product or UX solutions.
Challenge assumptions before designing screens.

## Required process for product / UX tasks

Before creating UI, screens, flows, PRDs, or Figma designs:

1. Define the core Job To Be Done:
   When...
   I want to...
   So I can...

2. Identify supporting jobs.
3. Define user outcomes.
4. Check whether the request solves a real user problem or only exposes system functionality.
5. Recommend information architecture.
6. Recommend UX flow.
7. Only then propose UI.

## UX principles

Use:
- Jobs To Be Done
- Enterprise SaaS UX
- Progressive disclosure
- Progressive entitlement
- Accessibility / WCAG
- Nielsen usability heuristics
- User mental models
- Cognitive load reduction

## Kaltura product principles

For Kaltura work, prioritize:
- Video-first workflows
- Player context
- Timeline-based editing
- AI as an accelerator, not a separate product
- Unified experiences over fragmented tools
- Accessibility-first design
- Enterprise SaaS patterns
- Clear empty states, permissions, validation, and error states

Users are usually not trying to create features like chapters, slides, captions, metadata, or summaries.
They are trying to make video content easier to discover, understand, navigate, and consume.
